ISSUE IDENTIFIED

Table: pinterest_oauth_tokens
- Vulnerability: Anonymous SELECT returns 200 with empty array
- Expected: Anonymous SELECT returns 403 Forbidden
- Root Cause: RLS policy uses USING (FALSE) allowing reads
- Severity: CRITICAL

Table: board_routing_config
- Vulnerability: Anonymous SELECT returns 200 with empty array
- Expected: Anonymous SELECT returns 403 Forbidden
- Root Cause: RLS policy uses USING (FALSE) allowing reads
- Severity: CRITICAL

FIX IMPLEMENTED (MIGRATION 0004)
────────────────────────────────
For both tables:
1. Enabled FORCE ROW LEVEL SECURITY (prevents owner bypass)
2. Dropped old "deny_all_rls" policy
3. Created explicit deny policies:
   - anon_deny_select: Denies SELECT for anon role
   - anon_deny_insert: Denies INSERT for anon role
   - anon_deny_update: Denies UPDATE for anon role
   - anon_deny_delete: Denies DELETE for anon role
   - Same for authenticated role
4. Revoked all privileges from PUBLIC, anon, authenticated
5. Granted full privileges only to service_role

───────────────
Anonymous SELECT: 403 Forbidden (with RLS error message)
Service-role SELECT: 200 OK (with results or empty array)
All write operations: Continue to be denied for anonymous users
